## 验收自检

- [x] 3 张视觉稿在 1440 和 390 宽度下都能正常打开；在 360 / 390 / 768 / 1024 / 1180 / 1200 / 1280 / 1440 宽度下没有横向滚动，H1 不换行（用脚本逐个宽度测量）
- [x] 所有颜色组合的对比度都达到 AA（见上表）
- [x] 字标用纯几何路径构造，不依赖字体；16px 的 favicon 仍能认出带斜杠的 0
- [x] 进行中档案的涂黑条是空占位，DOM 中没有真实内容
- [x] 所有动效都支持 `prefers-reduced-motion`；没有阻塞首屏阅读的动画
- [x] 失败的印章（失效、止损、超时）和命中的印章同样大小、同样显眼

## 验证过程中发现并已修复的问题

1. Hero 区块的 `padding` 简写覆盖了容器的左右边距，移动端文字贴到屏幕边缘
2. 涂黑条的隐藏提示框仍然占着滚动宽度，导致移动端页面宽 449px（视口 390）
3. 1440 宽时 H1 折成两行；「数据源」一行被大字号样式覆盖
4. 示例数据里 $HYPE 的结案收益（+18.4%）比最大涨幅（+18.1%）还高，逻辑上不可能，已改为最大涨幅 +21.6%
5. 「作废」印章的淡化被盖章动画覆盖，改用骨灰色表示

## 留给后续里程碑

- **M3**：组合版字标里的中文和副标题要转曲（字体入库之后）
- **M4**：柴犬素材需要透明背景的高清原图；视觉稿里的组件要按 tokens 重新实现，不能直接复制这里的 CSS
- **M5**：「我们盯什么」段落的实现方式：每个词条和它后面的分隔符放在同一个 `white-space: nowrap` 单元里，这样行首不会出现孤立的「·」（视觉稿已按这个方式处理）
- **M12**：全屏固定的 `feTurbulence` 噪点层在低端手机上的运行开销还没测过，放到性能测试时一起测

## 截图说明

`screenshots/` 里 6 张都是 Chrome DevTools 截的**整页图**：1440 宽为 1 倍 PNG，390 宽为 2 倍 JPG（模拟移动设备）。移动端截图时隐藏了吸底 CTA 条，因为它是固定定位的，整页拼接时会被印在页面中间。

截图时约 900px 处可能有一条很淡的分界：固定定位的噪点层只覆盖截图时的第一屏。这是截图工具的产物，页面本身没有这个问题。

**关于 DevTools 截图中途超时**：第一轮截图时，DevTools 在 390 宽、2 倍、整页截图时开始超时，之后所有参数都超时。后来做了对照实验：同样的参数下，开着噪点层和关掉噪点层都能成功截图，所以「噪点滤镜加大画布」这个推测**被排除了**。最可能的原因是当时 DevTools 控制的 Chrome 窗口被遮挡或在后台，macOS 暂停了出帧，第一个请求挂起后，后面的请求都排在它后面。但当时的窗口状态已经无法复现，所以**没有得到证实**。浏览器重启后截图一切正常。
